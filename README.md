# Parent_Mail

目や PC・スマートフォンの操作が苦手な高齢の親のための、Windows 用の Gmail メールソフトです。文字を大きく、画面をシンプルに、操作を少なくしています。

## 1. 特徴

- **Gmail 専用**。ログインには Gmail の「アプリパスワード」を使います。
- **アカウントは最大 5 つ**。名前を付けて、画面上部のボタンで切り替えます。選択中のアカウントは青く塗り、✓ を付けて見分けやすくしています。5 つが画面に収まらないときは、左右の矢印で動かせます。
- **画面は 3 つの領域**。上部バー（アカウントとフォルダ）、幅の狭いメール一覧、とても広いプレビューです。
- **文字の大きさを設定で変えられます**（12〜48pt）。プレビューだけを一時的に拡大・縮小することもできます。
- **本文は、まずプレーンテキストで表示します**。上部のチェックを入れると HTML 表示に切り替わります。外部の画像は、初期設定では読み込みません。
- **あやしいリンクと危険な添付ファイルに警告します**。実行ファイルなどは、開けないようにしています。
- **メールの作成・返信・転送は、別の窓で行います**。作成窓は同時に 1 つです。書きかけは自動で保存し、Gmail の下書きにも保存します。
- **削除は Gmail のごみ箱への移動だけです**。直後は「元に戻す」で戻せます。複数のメールをまとめて削除することもできます。
- **受信拒否リスト、振り分けルール、アドレス帳**（いずれもアカウントごと）、**ローカルでの検索**があります。
- **オフラインでも、保存済みのメールを読めます**。送れなかったメールは「送信トレイ」に残り、つながると再送します。

LLM を使う機能はありません。メールの内容を第三者に送ることもありません。

## 2. 動作環境

- Windows 10 / 11（64 ビット）
- WebView2 ランタイム（HTML 表示に使います。Windows 11 には最初から入っています）
- Gmail のアカウントと、アプリパスワード（2 段階認証を有効にして発行します）

## 3. 使い方

1. 配布された `Parent_Mail_日付-時刻.exe` を、好きなフォルダに置いて起動します。インストールは不要です。初回起動時に、exe と同じフォルダに `Data` フォルダが自動で作られ、データはそこに保存されます（手で作る必要はありません）。exe は、開発者向けの手順（4 章）で作ります。
2. 初回起動時に、メールアドレス、アプリパスワード、表示名を入力します。ログインできると、メールの読み込みが始まります。
3. 上部のボタンでアカウントとフォルダを切り替えます。メールは、一覧から選ぶとプレビューに出ます。
4. ウィンドウの右上の × を押すとアプリが終わります。送信待ちのメールがあるときは、確認が出ます。

メールの取得と、送信トレイの再送は、アプリを開いている間だけ動きます（5 分ごと）。Windows の起動時に自動で始まることはありません。

## 4. 開発者向け

C# + WPF（`net10.0-windows`）、MailKit（IMAP / SMTP）、WebView2、SQLite（ローカルのキャッシュ）、Windows 資格情報マネージャー（アプリパスワード）で作っています。

必要なもの: .NET SDK 10。

```
dotnet build -v q --nologo        # ビルド
dotnet test --nologo -v q         # 単体テスト
Start-ParentMail.bat              # ビルドして起動（アプリが開いている間は実行しない）
powershell -NoProfile -File tools\publish.ps1   # リリースビルド（publish\Parent_Mail_日付-時刻.exe）
python tools/gen_strings.py       # docs/plans/ui-strings.md から Strings.ja.cs を生成
```

- 実際の Gmail を使うテストは、通常は動きません。テスト用のアカウントを用意し、環境変数 `PARENTMAIL_TEST_USER` と `PARENTMAIL_TEST_APPPASSWORD`、そして `PARENTMAIL_LIVE_TESTS=1` を設定したときだけ動きます。値はコミットしないでください。
- 環境変数 `PARENTMAIL_DATA_ROOT`（絶対パス）で、データの置き場所を変えられます。Debug と Release のどちらでも最優先です。テスト専用です。
- 日本語を含むフォルダ名・ファイル名は、通常のケースとして扱っています。
- コードのコメントは日本語、設計書は英語で書きます。コミットメッセージの本文は日本語です。

## 5. データと安全性

- データは、exe と同じフォルダの `Data` フォルダに保存します（設定、メールのキャッシュ、添付ファイル、ログ）。初回起動時に自動で作ります。exe を OS と別のドライブに置けば、Windows が壊れて入れ直しになっても、データは残ります。
- アプリを別の場所へ移すときは、exe と `Data` フォルダをいっしょに移します。`Data` を消すと、この PC のメールのキャッシュと設定が消えます（Gmail 上のメールは消えません）。
- `Data` フォルダを作れない、または書き込めない場所（読み取り専用のフォルダなど）では、代わりに `%LOCALAPPDATA%\Parent_Mail\` に保存します。
- 開発用ビルド（Debug）は、これまでどおりです。exe の隣に `Data` があればそこ、無ければ `%LOCALAPPDATA%\Parent_Mail\` を使います。
- 自動では引き継ぎません。`%LOCALAPPDATA%\Parent_Mail\` の古いデータを使いたいときは、アプリを閉じて、その中身を `Data` フォルダへコピーします。
- アプリパスワードは Windows の資格情報マネージャーに保存します。`Data` フォルダには入りません。ファイルやログには書きません。Windows を入れ直したあとは、アカウントごとにパスワードの再入力が必要です（画面の案内に従います）。メールのキャッシュと設定は `Data` に残ります。
- ローカルのメールのキャッシュは、アプリ側では暗号化していません。同じ Windows アカウントを使える人は、読むことができます。
- ログには、メールの内容（件名、宛先、本文）を書きません。
- 送信は、確認も取り消しもなく、すぐに行います。
