## 1. Scope

`Account` model and repository, Credential Manager store, account-add screen (with login test), two account buttons (selected / non-selected, Issue #1) and the badge on the non-selected one, current-account state (`IAppState`). Delete/rename/re-entry/warning dialog are in PLAN-2.

## 2. Behavior

- Max 5 accounts (`MaxAccounts` = 5, Issue #8, Q92); the add action is disabled (greyed with [AC-04] 「アカウントは5つまでです」) at 5 (A4).
- Account-add window [WD-03] (title 「アカウントを追加」), MODAL (first launch: centered on the screen). Top to bottom: notice line [AC-01] 「Gmailのアプリパスワードが必要です。」; labels [AC-02] メールアドレス, アプリパスワード (PasswordBox, hidden), 表示名 (defaults to the part before @); a red error line; buttons [AC-03] 登録する* (default) and やめる. Field/tab order: メールアドレス, アプリパスワード, 表示名, 登録する, やめる; initial focus = メールアドレス; Enter in a field = 登録する (validate first); Esc = やめる. While the login test runs all fields are disabled and the button reads [AC-08] 「確認しています…」. No setup guide.
- Field errors (red error line, in place): empty/wrong address [AC-21] 「メールアドレスを正しく入れてください。」; empty password [AC-22] 「アプリパスワードを入れてください。」; empty name [AC-23] 「表示名を入れてください。」.
- First launch without an account: closing the window without adding (やめる, Esc or X) shows the confirm dialog [WD-09] (title 「アプリを終わりますか」) with text [AC-19] 「このまま閉じるとアプリは終わります。よろしいですか?」 and buttons 終わる / 戻る* (default 戻る; Enter = 戻る); 終わる exits the app, 戻る returns to the window (Q66). First launch with no account opens it directly without the Q31 dialog (A31); the Q31 dialog for later adds comes from PLAN-2's wrapper.
- Save flow (PQ28): validate fields (email format, non-empty); reject a duplicate address (case-insensitive) with the error line [AC-05] 「このメールアドレスは登録済みです」; run IMAP login and SMTP auth against `imap.gmail.com:993` (SSL) and `smtp.gmail.com:465` (SSL) via the gateways, showing a busy state; on failure show the red error line (login failed [AC-06] 「ログインできませんでした。アプリパスワードを確認してください。」; network [AC-07] 「接続できませんでした。ネットワークを確認してください。」) and save nothing; on success store the password in Credential Manager (target `ParentMail/<accountId>`, persistence LocalMachine-per-user "Enterprise"=false -> `CRED_PERSIST_LOCAL_MACHINE`), insert the account row, and trigger initial sync.
- Never write the password to SQLite, logs, or files.
- Account switch buttons (Issue #1, user decision 2026-10-16, Q91; replaces the former single switch button; row 1 of the two-row top bar, left end; app-shell PLAN 3.2; layout `window-layouts.md` 2.1): one side-by-side button per account (1 to 5), [TB-09] each showing that account's display name only (no arrow or hint). Selected = the current account: `Primary` fill, thick border (3-4 px), bold, leading check mark (✓, a symbol drawn by the view, not a localized string); pressing it does nothing but it still takes focus. Non-selected: white background, black text, thin border; pressing it switches. With only one account show just the selected button (no empty frame). Max width about 300 DIP; a longer name ends with an ellipsis and the full name is the tooltip; on the non-selected button reserve about 50 DIP for the badge FIRST. Overflow (Issue #8, Q92, A82-A87; `AccountSwitchViewModel` exposes the items, the strip view does the scrolling): the buttons sit in a horizontal `ScrollViewer` (scrollbar hidden, `HorizontalScrollBarVisibility=Hidden`) between the left edge and the HTML checkbox. A left arrow button and a right arrow button (symbols ◀ ▶, 56 x 56 DIP, `IsTabStop=false`, tooltip/AutomationName [TB-26] / [TB-27]) at the strip ends are visible only while the content is wider than the viewport; one press scrolls the next hidden button on that side completely into view (instant); the arrow is drawn disabled when nothing is further that way; mouse wheel scrolls sideways. The selected button is brought into view (`BringIntoView`) at startup and after every switch, add, delete and viewport resize. A button that receives keyboard focus (GotKeyboardFocus) is brought into view. Each arrow shows a red badge [same style as TB-10] with the sum of unread of the accounts hidden on that side (none when 0) and then adds [TB-28] to its tooltip. Widths: content width clamped to `AccountButtonMinWidthDip` (120) .. `AccountButtonMaxWidthDip` (300) with 1-2 accounts or `AccountButtonMaxWidthManyDip` (220) with 3-5 accounts. Keyboard: Tab stops in order button 1 to button N (N = 1 to 5; the arrows are not Tab stops); Enter and Space press; NO Left/Right arrow-key switching. On switch (unchanged): `IAppState.CurrentAccount` changes, the Inbox of that account is selected, selection cleared, preview zoom reset, search cleared. Last-used account id stored in settings (`last_account_id`).
- Badge (A44) [TB-10]: small red number badge (white text on #A80000), shown ONLY inside the NON-selected account button, right of the name, with that account's Inbox unread count (number) when > 0; refreshed after each sync of that account. The selected button never shows a badge (its own unread count is the Inbox folder badge, row 2). When the selection changes, the badge moves to the button that is now non-selected.
- Switching does not cancel running syncs (all accounts keep syncing).

## 3. Functions

- `IAccountRepository { GetAll(); Add(Account); Rename(id, name); Delete(id); }`
- `CredentialStore.Save/Get/Delete(accountId)` over P/Invoke (`CredWriteW`, `CredReadW`, `CredDeleteW`; blob = UTF-16 password; handle non-ASCII).
- `AccountService.ValidateAndAddAsync(email, password, displayName, ct)` returns `AddAccountResult { Ok, Duplicate, AuthFailed, NetworkError }`.
- `IAppState { string? CurrentAccountId (get/set); FolderKind CurrentFolder; long? SelectedMessageId; events CurrentAccountChanged, CurrentFolderChanged, SelectedMessageChanged }` (wave-0 contract; the `Account` object is resolved through `IAccountRepository.Get(id)`; switching = setting `CurrentAccountId`).
- `AccountSwitchViewModel { IReadOnlyList<AccountButtonItem> Items }` (1 or 2 items, in repository order; rebuilt on `CurrentAccountChanged`, account add/delete/rename, and unread-count change). `AccountButtonItem { AccountId, Name (display name), ToolTip (full name), IsSelected, Unread (int, 0 on the selected item), ShowBadge (= !IsSelected && Unread > 0), SelectCommand }`; `SelectCommand` sets `IAppState.CurrentAccountId` (does nothing when `IsSelected`). Names of the item type and members are a proposal; developer-lite may adjust them while keeping this behavior. This replaces the former `{ Label, OtherUnread, SwitchCommand }`.

## 4. Tests and done criteria

- Unit (fake gateways): duplicate rejected, auth failure saves nothing, success saves row and credential; max-5 enforcement (the 6th add is refused and AC-04 is shown; 5 accounts allowed); arrow badge = sum of unread of hidden accounts on that side (Issue #8; pure function of the item list and the visible range); badge count mapping (Issue #1: with two accounts the badge shows only on the non-selected item and never on the selected one; after switching it moves to the other item; 0 unread = no badge; one account = a single item without badge; pressing the selected item changes nothing; pressing the non-selected item sets `CurrentAccountId`).
- Manual (test Gmail account): add via real app password; wrong password rejected; the credential appears in Credential Manager; switching works with two accounts and with five accounts (Issue #8: arrows appear only when the buttons overflow, the selected button is always fully visible after a switch and after a restart, Tab onto a hidden button scrolls it into view, the hidden-unread badge shows on the right arrow, the layout still fits at 1024 px with 5 accounts) (Issue #1: selected button is blue + thick border + bold + check mark; long names show an ellipsis and tooltip; Tab/Enter/Space work, arrow keys do not switch; the layout fits at 1024 px wide).
