# Documentation Structure

- `docs/spec.md` — Confirmed specification. Authoritative baseline integrating design decisions and change history. Records "what is currently decided" concisely.
- `docs/detailed-spec.md` — Detailed specification. Expansion of `spec.md` to a level of detail usable for per-feature implementation plans (`docs/plans/<feature-name>/PLAN.md`).
- `docs/DECISIONS.md` — Background of decisions, comparative analysis, rejected alternatives, detailed reference information.
- `docs/QA.md` — Questions requiring the user's own decision, raised during implementation planning.
- `docs/RESOLVED-ISSUES.md` — Log of closed GitHub issues (issue number, title, labels, PR link).
- `docs/plans/<feature-name>/PLAN.md` — Per-feature implementation plans, created by developer-lite as each feature is planned.
- `docs/plans/ui-strings.md` — every user-visible Japanese string (fully approved); `docs/plans/window-layouts.md` — approved window layouts and window rules; `docs/plans/mockups/main-window.html` — main-window colour mockup; `docs/plans/pending-plan-edits.md` — edits developer-lite must apply to the PLANs.
